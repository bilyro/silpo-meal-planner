# Сценарій відео — «Сільпо Шеф» (≤ 5 хв)

Точна послідовність запису для подачі, за обов'язковою структурою організаторів:
**Проблема → Користувач → Рішення → Agent flow → MCP «Сільпо» → Demo → Цінність → Метрики →
Наступний крок.** Один сильний end-to-end сценарій, а не огляд функцій.

Все нижче виконується проти **справжнього акаунта Сільпо, без пісочниці**. Зібрати й наповнити
кошик — безпечно; ніщо тут не оформлює й не оплачує замовлення.

Тайм-бюджет (загалом 4:50, з запасом до ліміту 5:00):

| Блок | Час | Тривалість |
|---|---|---|
| Проблема | 0:00–0:15 | 15с |
| Користувач | 0:15–0:30 | 15с |
| Рішення | 0:30–0:50 | 20с |
| Agent flow | 0:50–1:15 | 25с |
| MCP «Сільпо» | 1:15–1:40 | 25с |
| **Demo** | 1:40–3:40 | **2:00** |
| Цінність | 3:40–4:00 | 20с |
| Метрики | 4:00–4:30 | 30с |
| Наступний крок | 4:30–4:50 | 20с |

## ⚠️ Пастка, яка може зіпсувати демо: мінімум 799 грн

**Сільпо взагалі не повертає `checkoutWebLink` — поле відсутнє, а не порожнє — якщо сума кошика
менша за 799 грн** (`{level:'error', type:'order', message:'order.cost.min',
context:{orderCostMin:799}}`; перевірено наживо, див. [`phase5-findings.md`](phase5-findings.md)
§4). Замість посилання бот коректно каже «⚠️ Оформлення поки недоступне: мінімальна сума
замовлення — 799 грн» — чесна інженерія, але жахливий фінальний кадр для відео, якщо це
трапиться в кадрі.

Дві речі зменшують суму вже ПІСЛЯ того, як ви написали запит: `computeQuantity` обмежує кожну
позицію реальним залишком на складі філії, а інгредієнти, яких не знайшли, потрапляють у
«⚠️ Не знайшли» і нічого не додають до суми.

**Тому: просіть план, достатньо великий, щоб вийти на ~1100–1400 грн, і зробіть репетиційний
прогін заздалегідь**, щоб побачити реальну суму. План вечерь на 2 дні для двох виходить приблизно
на 300–500 грн і *не* подолає поріг. Робочі формулювання:

- «Сплануй вечері на 5 днів для сімʼї з 4 осіб, без свинини, до 1800 грн»
- «Сплануй обіди і вечері на 3 дні для сімʼї з 4 осіб, без свинини, до 1800 грн»

Тримайте заявлений бюджет **вищим** за очікувану суму, щоб список показав «(бюджет 1800 ✅)», а не
⚠️. Якщо на репетиції сума не дотягує до 799 грн — додайте днів/прийомів їжі до запиту, або в уже
підібраному списку напишіть «додай ще один день» і підтвердьте ще раз перед записом.

## Перед записом

1. **`PUBLIC_BASE_URL` має бути HTTPS-адресою, доступною з інтернету**, якщо посилання на вхід
   відкриватиметься з телефону. `cloudflared tunnel --url http://localhost:3000`, вставте HTTPS-URL
   у `.env`, тоді `DELETE FROM oauth_clients; DELETE FROM oauth_pending;`, щоб DCR-клієнт
   перереєструвався з новим redirect_uri. Запис на комп'ютері, де працює сервер, обходиться без
   тунелю.
2. **З 9 вересня підключення має додатковий крок**: після входу в Сільпо `/auth/callback` показує
   одноразовий 6-значний код замість того, щоб одразу завершити підключення — його треба ввести
   назад у той самий чат Telegram, щоб підтвердити звʼязок (закриває вразливість викрадення
   акаунта; див. README, розділ «Known Issues»). Проженіть це один раз заздалегідь, щоб не стало
   сюрпризом у кадрі, або взагалі пропустіть запис підключення (див. пункт 4 нижче).
3. `docker compose up -d postgres && npm run migrate && npm run dev` — переконайтесь, що
   `GET /healthz` повертає `{"status":"ok"}`.
4. **Очистіть акаунт:** у Telegram надішліть `/clear` → «🗑 Так, очистити». Залишений кошик після
   репетиції буде повторно використаний `ensureCartContext` і роздує підсумкову суму.
5. Вирішіть, чи показувати крок OAuth. Щоб показати — спочатку надішліть `/logout`: це скидає
   токени й історію розмови для справжнього холодного старту. Якщо вхід у день запису нестабільний
   — пропустіть: запишіть уже підключений акаунт, а онбординг опишіть голосом (це також дозволяє
   оминути крок із кодом підтвердження вище).
6. Тримайте **застосунок Сільпо** відкритим на другому пристрої, залогінений у той самий акаунт, на
   екрані кошика. Найсильніший момент відео — коли той самий кошик з'являється там.
7. Підготуйте термінал із запитами до `tool_call_log` (розділ «Метрики» нижче).
8. Переконайтесь, що в профілі збережено **харчове обмеження** (напр. «без свинини»). Саме це
   робить враження, що агент знає користувача, а не вгадує.
9. Перегенеруйте лог одразу до або одразу після зйомки: `npm run export-log` — найсвіжіший
   `docs/tool-call-log.md` є обов'язковим артефактом подачі й має відображати саме цей прогін.

**Не натискайте** на камеру **💸 Дешевше** чи **✏️ Прибрати позицію** — вони ведуть до вільного
тексту, а не підключені до власної логіки напряму. Залиште їх непритиснутими, або скажіть голосом,
що вільний текст («прибери лосось», «додай чіпси») уже обробляється через цикл агента, якщо про це
попросити.

## Запис — блок за блоком

### 0:00–0:15 · Проблема

Голос за кадром на тлі порожнього чату Telegram, або телефон поруч із паперовим списком покупок:

> «Що приготувати?» → «Що купити?» → 30-40 хвилин щотижня. Список пишеться десь окремо від
> застосунку, промо-акції перевіряються вибірково або не перевіряються взагалі, і кошик виходить
> дорожчим і менш повним, ніж міг би бути.

### 0:15–0:30 · Користувач

> Це та сама рутина для кожної родини, яка регулярно замовляє продукти в Сільпо — особливо коли
> є харчові обмеження чи алергії, які треба пам'ятати щоразу. Сільпо вже знає склад сім'ї,
> обмеження й адресу — просто ніхто не використовує ці дані, щоб відповісти на реальне запитання.

### 0:30–0:50 · Рішення

> «Сільпо Шеф» — телеграм-агент, який доводить це до кінця: одне повідомлення на вході, реальний
> зібраний кошик і посилання на оформлення — на виході. Все через офіційний Silpo MCP-сервер,
> проти справжнього акаунта, без пісочниці й без вигаданих даних.

*(Показати телефон: чат з одного боку, застосунок Сільпо з іншого — візуальний ряд для всього
відео.)*

### 0:50–1:15 · Agent flow

> Модель вирішує ЩО і КОЛИ, а не ЯК. Чотири кроки — встановити контекст кошика, підібрати товари,
> зафіксувати список, прочитати кошик і видати посилання — виконує звичайний детермінований код,
> а не імпровізація LLM. І модель фізично не має інструменту, який може змінити кошик: усі
> мутуючі дії доступні лише коду, і без натискання кнопки нічого не записується.

### 1:15–1:40 · MCP «Сільпо»

> Бот читає всі 40 інструментів з реального сервера під час старту — жодна форма аргументів не
> захардкоджена. Моделі доступні 33 read-інструменти з шести категорій: профіль, пошук товарів,
> акції, кошик, доставка, лояльність. Сім інструментів, які можуть змінити акаунт, — недоступні
> моделі взагалі, лише нашому коду. Кожен виклик логується: інструмент, аргументи, статус,
> тривалість.

*(Опційний візуал: прокрутка `docs/tools.json`, або таблиця інструментів зі слайда 4
README/pitch-deck.)*

### 1:40–3:40 · Demo — наскрізний сценарій

Це кульмінація — дайте їй найбільше часу, один чистий безперервний прогін.

**Підключення** *(пропустити, якщо акаунт вже підключено; розповісти голосом натомість)*:
`/start` → «🔐 Підʼєднати Сільпо» → вхід у Сільпо → ввести 6-значний код підтвердження назад у
чат. Бот відповідає зі справжнього профілю:

> Готово, {імʼя}! Я бачу вашу {сімʼю з N осіб}.
> Обмеження харчування: {…}.

Сказати: *тут нічого не набрано мною вручну — це профіль і обмеження, прочитані наживо з Silpo
MCP.*

**Запит і меню.** Написати одним повідомленням:

> Сплануй вечері на 5 днів для сімʼї з 4 осіб, без свинини, до 1800 грн

Бот показує (індикатор набору тексту, тоді):

> 🍽 **Меню на 5 днів**
> **День 1** — *{страва}* · • {інгредієнт} — {кількість} …
> Підтверджуєте меню? **[✅ Так] [✏️ Змінити]**

Наголосити: ніде свинини, розраховано на чотирьох — жодного з цих фактів не було в набраному
повідомленні.

**✅ — підбір по реальному каталогу.** Натиснути **✅ Так**. За одним натисканням: встановлюється
контекст кошика (філія, тип доставки, перший вільний слот), кожен інгредієнт пошуковується
пакетно, для кожного обирається один товар.

> 🧾 **Список: N позицій — 1 2xx грн** (бюджет 1800 ✅)
> 🔥 K акційних · 🔄 M замін
> • {Товар} × {кількість} — {ціна} грн 🔥
> **[🛒 Зібрати кошик]**

Розповісти: 🔥 — це справжня акція, зчитана по кожному товару з полів `specialPrices`/`oldPrice`;
🔄 — заміна, отримана через `silpo_get_replacements`, бо первинний вибір закінчився на складі.
*Кожна назва й ціна на цьому екрані взяті з результату інструмента — модель не може їх
вигадати.*

**🛒 — справжній кошик і посилання на оформлення.** Натиснути **🛒 Зібрати кошик**. Один пакетний
виклик `silpo_add_or_update_cart_products`, тоді кошик зчитується назад:

> 🛒 **Кошик зібрано** — N поз., {сума} грн
> 💳 Бонусів доступно: {баланс}
> 👉 **Оформити замовлення**

**Перейти в застосунок Сільпо**, оновити кошик — ті самі товари, та сама філія, той самий слот.
Затримати цей кадр на 2-3 секунди — це найсильніший момент усього відео. Зазначити, що бот
свідомо зупиняється на посиланні на оформлення — у MCP немає інструмента для оформлення
замовлення, і агент ніколи не має платити.

### 3:40–4:00 · Цінність

> Для гостя: менше часу на рутину, повніший і дешевший кошик — акції перевірені по кожній позиції,
> а не вибірково, і жодного ризику купити заборонений продукт, бо обмеження — тверде правило в
> коді, не прохання до моделі. Для бізнесу: більші кошики і вище викуп акційних товарів, бо агент
> перевіряє те, що покупець вручну ніколи не перевіряє повністю.

### 4:00–4:30 · Метрики

Перейти в термінал:

```sql
SELECT tool, ok, ms, created_at
FROM tool_call_log
WHERE user_id = (SELECT id FROM users ORDER BY id DESC LIMIT 1)
ORDER BY id;
```

Прокрутити результат — уся сесія: читання профілю, ланцюжок контексту кошика, пакетний пошук,
пошук замін, запис у кошик, зчитування кошика назад — з тривалістю кожного виклику й ознакою
успіху. Далі:

```sql
SELECT tool, count(*), round(avg(ms)) AS avg_ms
FROM tool_call_log GROUP BY tool ORDER BY count(*) DESC;
```

Сказати вголос, підставивши реальні числа з цього прогону: *час від запиту до посилання на
оформлення, кількість викликів MCP по N різних інструментах, частка акційних товарів і частка
замін — вони вже показані наживо як «🔥 K акційних · 🔄 M замін» — і все це коштувало ~$0.003 за
запит завдяки кешуванню промпту на блоці інструментів.*

### 4:30–4:50 · Наступний крок

> Той самий агент — усередині самого застосунку Сільпо, оскільки весь потік вже завершується на
> справжньому checkout Сільпо. План уже зберігається в базі — «Повтори минулий план» працює
> сьогодні, тож щотижневий авто-план по четвергах — наступний логічний крок. І інверсія: замість
> підбирати акції під обране меню, будувати меню з цьогорічних акцій напряму.

## Що робити, якщо щось пішло не так у кадрі

| Проблема | Що ви бачите | Як виправити |
|---|---|---|
| Немає посилання на оформлення | «⚠️ Оформлення поки недоступне: мінімальна сума замовлення — 799 грн» | Кошик нижче мінімуму. Написати «додай ще два дні», підтвердити ще раз, перезібрати. Запобігти репетиційним прогоном заздалегідь. |
| OAuth `400 Invalid or expired state` | Сторінка помилки Сільпо замість callback | `PUBLIC_BASE_URL` недоступний із пристрою, що відкрив посилання. Записувати на комп'ютері, де працює сервер, або налаштувати тунель. |
| Завис на екрані коду підтвердження | сторінка callback показує код, далі нічого не відбувається | Треба реально ввести цей код назад у той чат Telegram, де було натиснуто `/start`, — це справжній додатковий крок, а не збій відображення. |
| «Ваш звʼязок із Сільпо застарів» | на будь-якому кроці | Токени прострочені. `/start` і підключити акаунт заново. |
| «На жаль, не вдалося підібрати жодного товару» | після ✅ | Майже завжди застарілий контекст кошика. `/clear`, тоді підтвердити меню ще раз. |
| Бот питає адресу доставки | після ✅ | В акаунта немає збереженої адреси. Відповісти простим текстом: «Київ, вулиця Хрещатик, 1». Варто перевірити заздалегідь, щоб це не з'явилось посеред запису. |
| Меню з'являється без кнопок ✅/✏️ | після запиту | Модель розповіла меню текстом замість виклику `propose_menu`. Надіслати запит ще раз; промпт робить це рідкісним, але не неможливим. |
| «Досягли денного ліміту повідомлень» | після кількох повідомлень вільним текстом | Ліміт 10 повідомлень/добу. Натискання кнопок (✅/🛒) не рахуються, тож звичайне демо на кнопках у нього не впреться — а от репетиції з великою кількістю вільного тексту можуть. Дочекатись наступного дня, або на час запису підняти `DAILY_MESSAGE_LIMIT` у `.env`. |

## Після запису

Надіслати `/clear` → «🗑 Так, очистити», щоб спорожнити справжній кошик, тоді ще раз
`npm run export-log`, щоб `docs/tool-call-log.md` відображав саме поданий прогін — обов'язковий
артефакт подачі.
